# ## The one rise in this record, and why it is not a regression
#
# Until 0.60.4 this file was measured by three regexes, the first of which was
# `>\s*([A-Z][^<>{}\n]{2,})\s*<`. QRME and JIM both abandoned that reader
# rounds ago — three separate regexes over the same source each hid real
# strings — and moved to `app/scripts/jsx-text.mjs`, which parses the file
# with TypeScript's own parser and returns every `JsxText` node. This product
# kept the regex, and nothing had compared the two.
#
# The three characters that pattern forbids are the three shapes most of this
# console's prose takes:
#
#   * `\n` — any sentence long enough to wrap. The paragraph in
#     `ProblemNotice` explaining what a problem report does and does not carry
#     is four source lines: one string to a reader, no string at all to this.
#   * `{}` — any sentence with a value in the middle. `VersionGuard` reads
#     *This app is v{CONSOLE_VERSION}, but the backend at {getBase()} is
#     v{backend} — an older install is still running*. Three interpolations
#     cut that into fragments and the pattern rejected every one. The screen
#     whose whole job is to explain why an install answers "Not Found" was the
#     least visible thing in the console.
#   * a leading capital — *no tenant selected*, *entries verified*,
#     *what reaches into this vault*, *one per integrating system*.
#
# Fifty-six strings, a quarter of the true total, and hidden in the direction
# that makes a ratchet look satisfied. Both localization rounds above were
# graded against a number that was low.
#
#     asked     how much English does this pattern match
#     mattered  how much English does a person read
#

# ## 0.60.6 — the second rise, and what a word boundary is a claim about
#
# The reader that got honest at 0.60.4 was still asking one question wrong. It
# counted a string as English if it matched `[A-Za-z]\s[A-Za-z]` — a letter, a
# space, a letter — or was a single capitalised word. Four headings on the very
# screen this round localizes have neither:
#
#     Role &amp; industry
#     Decision-making &amp; oversight
#     Bottlenecks &amp; obsolescence
#     Human-in-the-loop
#
# Every space in the first three sits beside an HTML entity, so the character
# before it is `;` and the character after it is `&`. The fourth has no space at
# all. All four are English a person reads off the screen, and none of them was
# ever counted. So were `Re-verify`, `publish — out`, `hard — gone`, `soft —
# recoverable`, `Keys &amp; Retention` (twice) and `append-only · SHA-256
# hash-chained`.
#
#     asked     is there a space with a letter on both sides
#     mattered  does this read as more than one word
#
# Fourteen strings, and this is the third time in this arc that the measurement
# was the bug: `>\s*([A-Z][^<>{}\n]{2,})\s*<` at 0.60.4, three separate
# regexes over one source before that, and now a word boundary that only knows
# about spaces. Each time the fix raised the number before any work lowered it,
# which is the only order that is honest.
#
# `_PHRASE` decodes entities first — the reader sees the `&` the browser draws,
# not the `&amp;` the source stores — and then looks for two runs of letters
# joined by anything that is not `/`, `_` or `.`. Those three are excluded
# deliberately, and each excludes a real string in this console: a path
# (`POST /profiles/{id}/chat → 500`), an identifier (`PDI_ADMIN_TOKEN`) and a
# filename (`report.pdf`). `test_the_reader_reads_more_than_a_space` holds both
# halves — the four headings must count, the three non-sentences must not — so
# a later simplification of the pattern cannot quietly re-blind it.
#
