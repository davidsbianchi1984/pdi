# ## What this counts, and why counting it is the point
#
# A floor answers one question every run — is the number satisfied — and that
# is exactly the question that keeps passing after the number stops meaning
# anything. Asking the second question, *is it still near what it measures*,
# needs the measurement, and a literal inside an assertion has none attached.
#
#     asked     is the number satisfied
#     mattered  is the number still near what it measures
#
# 0.58.8 found the route reader's floor was written when the console was the
# only client. 0.58.9 found the localizer's was ten against nine hundred and
# forty-five in the largest product. 0.59.0 applied the standard to everything
# reachable, in all three:
#
#     l10n asked, per shell        10 against 48-62        ratio 0.19
#     l10n held, per shell         10 against 51-64        ratio 0.18
#     path literals, all surfaces  40 against 183          ratio 0.22
#     console call sites          100 against 121          ratio 0.83  held
#     native call sites            20 against 35-36        ratio 0.57  held
#
# The rows that passed are as informative as the ones that did not. A literal
# copied into three repositories is calibrated for whichever of them was
# smallest when it was written, so the same number is an honest floor in one
# product and decoration in another — and nothing in either could tell,
# because neither had the measurement attached.
#
# Those are now in `ratchets.py`, registered with the way to measure the same
# quantity, and audited every run. The rows below are what is left.
#
# ## How a row leaves this file
#
# Register it in `ratchets.py` with a `measure` callable and change the
# assertion to `ratchets.floor("name")`. The sweep finds bare literals only,
# so registering removes the row without anybody editing this list — and the
# registered floor is then checked against reality on every run.
#
# Not every row here is wrong. Some of these numbers are small fixed
# cardinalities that will never drift. Telling those apart from the decoration
# requires knowing what each one measures, which is the work of registering
# it, which is why they are counted rather than guessed at.
#
# The ceiling does not move up because a floor was written. It moved up once,
# here, because the sweep was widened — and the distinction is the whole
# reason a number like this is worth keeping.
#
#     asked     did the backlog grow
#     mattered  did the suite get worse, or did the instrument get better
#
# The sweep used to take any comparison against an integer of five or more.
# Five stood in for "is this a floor at all", badly: it hid an `assert n >= 2`
# over a shell building a hundred and twenty-seven requests, and lowering it
# would have swept in fifty-two assertions about single response bodies that
# no ratchet could ever measure. It now asks what the left side of the
# comparison is — a count of something the suite went and found, or a value
# pulled out of what something returned.
#
# Rows that appeared the day that changed were always there. A backlog that
# only ever falls, when the thing generating it can be narrowed, is a number
# about the sweep rather than about the suite.
#
#
# ## Not floors: a value that is not a size
#
# The sweep matches the *shape* `assert <something> >= <int>`, and in the
# sibling products that shape caught comparisons where the integer is not a
# size at all — a status code, somebody's age, a heart rate. Those cannot be
# registered as ratchets, because there is no "four-fifths of what is actually
# there" to raise them toward.
#
#     asked     is this an `assert x >= <int>`
#     mattered  is the int a floor on something that can grow
#
# **This vault has none.** Every comparison in this suite that is not written
# as `len(...)` or `sum(...)` — `controls`, `n`, `matched`, `reached`,
# `english + calls` — is still a count of a swept surface, held in a local
# variable rather than spelled as a call. All of them are floors and all of
# them belong in `ratchets.py`.
#
# The mechanism is carried here anyway, with an empty list, for the reason the
# platform-claim guard is: the shape spreads by being copied between suites,
# and the day a status code or an age arrives here the sweep will already know
# the difference. An empty exemption is not a dormant one — the two guards
# below run against it every time, and the second is what keeps it empty
# honestly rather than by luck.
#
# `test_every_exempted_comparison_is_still_there` checks each named row is
# really written somewhere, and `test_a_count_can_never_be_exempted` refuses
# any exemption whose comparison is against `len(...)` or `sum(...)`: a count
# of a swept surface is always a floor, whatever prose sits above it. That is
# the guard that stops this list becoming the place a real floor goes to be
# excused when somebody wants the backlog number to fall.
